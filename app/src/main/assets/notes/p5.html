1. Topic Overview

Definition

Phase V: Model Evaluation checks whether the model is good enough — technically AND for the business — before it goes to production. It validates the model against the untouched test set and against the Phase I KPIs, and makes the deploy / iterate / stop decision.

One-line memory hook: Phase V = "Is it GOOD ENOUGH?" — technical metrics + business KPIs + ethics.

Why It Is Important

  • Prevents deploying models that look good in the lab but fail the business.
  • Catches bias, unfairness, and accuracy paradoxes before customers are harmed.
  • Connects the loop back to Phase I success criteria — the whole point of the project.

Where It Is Used

  • After Phase IV, before Phase VI, in every iteration.
  • Repeated in production as ongoing monitoring feeds re-evaluation.

2. Key Concepts

2.1 Two-Level Evaluation (core CPMAI idea)

Level Question Example
Technical evaluation Does the model perform well statistically? Precision 92% on test set
Business evaluation Does it achieve the Phase I KPI/ROI? Fraud losses actually reduced 20%? Analysts adopt it?

Both must pass. A technically brilliant model that misses the business KPI = failure.

2.2 Confusion Matrix (classification)

                     PREDICTED
                  Fraud     Not Fraud
ACTUAL  Fraud      TP          FN   ← missed fraud (costly!)
        Not Fraud  FP          TN
  • TP (True Positive): predicted fraud, was fraud ✔
  • TN (True Negative): predicted clean, was clean ✔
  • FP (False Positive): predicted fraud, was clean ✘ (Type I error — annoyed customer)
  • FN (False Negative): predicted clean, was fraud ✘ (Type II error — money lost)

2.3 Classification Metrics (must memorize)

Metric Formula Plain Meaning When It Matters
Accuracy (TP+TN)/All Overall % correct Balanced classes only
Precision TP/(TP+FP) Of flagged positives, how many were right? When FP is costly (spam filter blocking real mail)
Recall (Sensitivity) TP/(TP+FN) Of actual positives, how many did we catch? When FN is costly (cancer, fraud — don't miss!)
F1 Score 2·(P·R)/(P+R) Balance of precision & recall Imbalanced data, need both
Specificity TN/(TN+FP) Of actual negatives, how many correctly cleared? Medical screening contexts
AUC-ROC Area under ROC curve (0.5=random, 1=perfect) Overall ranking ability across thresholds Comparing classifiers

2.4 The Accuracy Paradox (favorite exam trap)

  • Dataset: 99% legit, 1% fraud.
  • A dumb model predicting "never fraud" scores 99% accuracy — while catching zero fraud (recall = 0%).
  • Lesson: With imbalanced data, accuracy is misleading → use precision, recall, F1, AUC.

2.5 Regression Metrics

Metric Meaning
MAE (Mean Absolute Error) Average size of errors (easy to interpret)
MSE / RMSE Squared errors — punishes big misses more; RMSE in original units
R² (R-squared) % of variation explained (closer to 1 = better)

2.6 Threshold Tuning & Precision-Recall Tradeoff

  • Classification outputs a probability; the threshold decides the cutoff.
  • Lower threshold → more recall, less precision (catch more fraud, more false alarms).
  • Higher threshold → more precision, less recall.
  • The business decides the tradeoff (cost of FP vs FN).

2.7 Bias, Fairness & Ethical Evaluation

  • Test performance across groups (gender, age, region): does the model treat groups fairly?
  • Check for disparate impact (e.g., loan approval rates differing unfairly).
  • Verify explainability requirements are met (reason codes, SHAP/LIME reports).
  • Regulatory review: RBI/fair-lending, GDPR "right to explanation", HIPAA.

2.8 Evaluation Against the Test Set — and Beyond

  • Final metrics come from the locked test set (first time it's touched!).
  • Optionally: backtesting (replay on historical periods), shadow testing / A/B pilot (run alongside current process before full rollout).

2.9 The Phase V Decision

  • Deploy → proceed to Phase VI.
  • Iterate → loop back (better features? more data? new algorithm?).
  • Stop → business case no longer holds. (Stopping a bad model IS a success of governance!)

3. PMI CPMAI Exam Focus

What the Exam Expects

  • Compute/interpret precision, recall, F1, accuracy from a confusion matrix.
  • Recognize the accuracy paradox in imbalanced scenarios.
  • Choose the right metric for the business context (FN-costly → recall; FP-costly → precision).
  • Distinguish technical vs business evaluation — both required.
  • Fairness/bias checks belong here.

Frequently Tested

  1. "1% fraud, model 99% accurate but catches nothing" → accuracy paradox → use recall/F1.
  2. "Cancer screening — which metric?" → Recall (missing a case is worst).
  3. "Spam filter deleting genuine emails — which metric?" → Precision.
  4. Reading a confusion matrix.
  5. "Model meets accuracy target but business KPI unmet" → evaluation must include business KPI; revisit Phase I criteria.

Common Misconceptions

Misconception Truth
"Accuracy is the universal metric" Misleading with imbalance — use P/R/F1/AUC
"Technical success = project success" Business KPI must also be met
"Evaluation = one number" Includes fairness, explainability, robustness, business fit
"Never stop a project after building" Stop is a valid, healthy Phase V outcome
"Threshold is a data science decision only" The business owns the FP/FN cost tradeoff

4. AI Project Manager Perspective

Responsibilities

  • Ensure evaluation covers technical + business + ethical dimensions.
  • Translate metric tradeoffs into business language (₹ cost of FP vs FN) for stakeholders.
  • Facilitate the deploy / iterate / stop decision with evidence.
  • Ensure test-set integrity (no leakage, first-time use).
  • Commission bias/fairness audits; document for regulators.
  • Report results against Phase I success criteria, not just lab metrics.

Stakeholders

Stakeholder Role
Business sponsor Judges KPI achievement; owns tradeoff choices
Data scientists Produce metrics, error analysis
Compliance/risk/legal Fairness, explainability sign-off
End users Usability/pilot feedback
Model risk / validation team (in banks) Independent model validation

Risks

  • Evaluating on contaminated test data (leakage) → false confidence.
  • Metric-KPI mismatch — optimizing the wrong number.
  • Undetected bias → legal/reputational damage.
  • Pressure to deploy despite failed criteria ("we spent so much already" — sunk-cost trap).
  • Ignoring operational readiness signals (latency, cost per prediction).

Best Practices

  • Define evaluation criteria in Phase I, apply them unchanged in Phase V.
  • Use multiple metrics + confusion matrix, never accuracy alone.
  • Run subgroup fairness analysis and document it.
  • Pilot/shadow test before full deployment when stakes are high.
  • Make the go/iterate/stop decision formal and documented.

5. Real-World Example (Banking — Fraud Model Evaluation)

Scenario: Fraud model from Phase IV reaches evaluation. Phase I KPIs: cut fraud losses 20%, false-positive rate ≤2%.

Step by step: 1. Test-set run (first touch): Confusion matrix on 100,000 held-out transactions (1,000 actual frauds): - TP = 850, FN = 150, FP = 1,800, TN = 97,200. 2. Metrics: - Recall = 850/1000 = 85% (fraud caught) - Precision = 850/2650 = 32% - FP rate = 1800/99000 ≈ 1.8% ✔ (≤2% target) - Accuracy = 98% — noted but ignored as primary (imbalanced data!). 3. Business translation: 85% recall ≈ ₹8.5 Cr of ₹10 Cr fraud caught → projected loss reduction ~23% ✔ beats the 20% KPI. 4. Threshold review with business: Lowering threshold → recall 90% but FP rate 3.1% (breaches customer-experience KPI) → business keeps current threshold. 5. Fairness audit: Flag rates checked across customer segments/regions — no disparate impact found; documented for RBI audit. 6. Explainability: Top reason codes per alert available for analysts ✔. 7. Shadow test: 2-week parallel run alongside the old rules engine confirms results on live data. 8. Decision: DEPLOY → Phase VI, with monitoring plan attached.

7. Key Formulas or Frameworks

Must-Memorize Formulas

Accuracy  = (TP + TN) / (TP + TN + FP + FN)
Precision = TP / (TP + FP)          "Of predicted positives…"
Recall    = TP / (TP + FN)          "Of actual positives…"
F1        = 2 × (Precision × Recall) / (Precision + Recall)

Memory Hooks

  • Precision → Predicted (both P!): denominator = predicted positives (TP+FP).
  • Recall → Reality: denominator = real positives (TP+FN).
  • FN = the dangerous miss in medical/fraud contexts.

Two-Level Evaluation Framework

Technical pass + Business KPI pass + Ethics pass → Deploy. Any fail → Iterate/Stop.

9. Exam Tips

Memory Tricks

  • Precision = Predicted; Recall = Reality.
  • "Cancer & Crime → Recall" (never miss). "Spam → Precision" (never block good mail).
  • Accuracy + imbalanced data mentioned together = paradox trap → answer uses P/R/F1.
  • Phase V motto: "Technically good AND business good."

Keywords

  • "Untouched/held-out test set"
  • "Business KPI validation" against Phase I
  • "Fairness/bias evaluation"
  • "Deploy / iterate / stop"

Differentiators

Pair Difference
Precision vs Recall FP-focused vs FN-focused
Sensitivity vs Specificity Catch positives vs clear negatives
Type I vs Type II FP vs FN
Technical vs Business evaluation Metrics vs KPI/ROI achievement

Traps

  • Choosing accuracy for imbalanced scenarios → wrong.
  • "Model passed metrics, deploy without business review" → wrong.
  • "Adjust the model using test results repeatedly" → test set contamination.
  • Sunk-cost reasoning ("we invested too much to stop") → wrong; stop is valid.
