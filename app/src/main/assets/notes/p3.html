1. Topic Overview

Definition

Phase III: Data Preparation is where raw data is cleaned, transformed, labeled, and engineered into a form suitable for model training. It answers: "HOW do we make the data usable?"

One-line memory hook: Phase III = HOW to prepare the data — the "kitchen work" before cooking the model.

Why It Is Important

  • Most time-consuming phase: typically 60–80% of total AI project effort goes into data preparation. (Classic exam fact!)
  • Model quality is capped by data quality — great preparation > fancy algorithms.
  • Poor preparation causes bias, leakage, and failed deployments.

Where It Is Used

  • After Phase II approval, before model development, in every iteration.
  • Whenever new data arrives or pipelines are updated in production.

2. Key Concepts

2.1 Data Cleaning (Cleansing)

Fixing the problems found in Phase II:

Task Meaning Example
Handling missing values Remove rows, or impute (fill) with mean/median/mode or predictions Fill missing income with median income
Removing duplicates Deduplicate records Same customer entered twice
Fixing errors Correct invalid entries Age = 250 → correct or remove
Handling outliers Detect extreme values; keep, cap, or remove based on context ₹10 crore grocery bill
Standardizing Unify formats/units "M/F" vs "1/2" → single scheme; kg vs lbs

Important nuance: In fraud/anomaly use cases, outliers may BE the signal — don't blindly remove them!

2.2 Data Transformation

Technique Meaning Example
Normalization (Min-Max scaling) Rescale values to 0–1 range Salary 20K–500K → 0–1
Standardization (Z-score) Rescale to mean 0, std dev 1 Common for many ML algorithms
Encoding categorical data Convert categories to numbers One-hot encoding: City → [1,0,0]
Binning Group continuous values into buckets Age → 18–25, 26–40, 41+
Aggregation Summarize detail into higher level Daily sales → weekly sales

2.3 Feature Engineering (heavily tested)

  • A feature = an input variable the model learns from.
  • Feature engineering = creating new, more informative features from raw data using domain knowledge.
  • Examples:
  • From transaction timestamp → "transactions in last 1 hour" (fraud signal).
  • From date of birth → "age".
  • From two columns → ratio ("debt-to-income ratio").
  • Feature selection = choosing the most relevant features and dropping noise.
  • Often the biggest driver of model performance.

2.4 Data Labeling (Annotation)

  • Attaching the correct answer (label) to each example for supervised learning.
  • Examples: marking emails as spam/not-spam; drawing boxes around tumors in X-rays.
  • Methods: internal experts, outsourced labeling teams, crowdsourcing, programmatic/weak labeling.
  • Often expensive and slow — a major project cost the PM must plan.
  • Label quality matters: inconsistent labelers → noisy labels → weak model. Use labeling guidelines and inter-annotator checks.

2.5 Data Augmentation & Synthetic Data

  • Augmentation: create modified copies of existing data to expand the dataset — rotate/flip/crop images, add noise to audio.
  • Synthetic data: artificially generated data mimicking real data — useful when real data is scarce, expensive, or privacy-restricted.

2.6 Dataset Splitting

Split Purpose Typical Share
Training set Model learns from this ~70–80%
Validation set Tune settings (hyperparameters) ~10–15%
Test set Final unbiased performance check ~10–15%
  • Golden rule: Test data must stay unseen until final evaluation.
  • Data leakage = information from test/future data sneaking into training → falsely great results in the lab, failure in production. Big exam keyword!

2.7 Data Pipelines, ETL/ELT

  • ETL: Extract → Transform → Load (transform before storing).
  • ELT: Extract → Load → Transform (store raw, transform later — common with data lakes).
  • Data pipeline: automated, repeatable flow of these steps — essential because preparation repeats every iteration and in production.
  • Related storage: Data warehouse (structured, curated) vs Data lake (raw, all formats).

2.8 Class Imbalance Handling

  • When one class is rare (fraud = 0.1% of transactions).
  • Fixes: oversampling minority (e.g., SMOTE), undersampling majority, class weights.
  • Prepares data so the model doesn't just predict "not fraud" always.

3. PMI CPMAI Exam Focus

What the Exam Expects

  • Phase III is the most time/effort-consuming phase (60–80%).
  • Distinguish cleaning vs transformation vs feature engineering vs labeling.
  • Understand train/validation/test splits and data leakage.
  • Know when augmentation/synthetic data helps.
  • Recognize pipeline/automation importance for iteration.

Frequently Tested

  1. "Which phase consumes the most effort?" → Phase III.
  2. Missing value handling and imputation.
  3. Feature engineering definition and examples.
  4. Labeling for supervised learning — cost/quality issues.
  5. Data leakage scenarios.
  6. Outliers in fraud contexts (don't auto-delete).

Common Misconceptions

Misconception Truth
"Modeling takes the most time" Data preparation does (60–80%)
"Always delete outliers" In anomaly/fraud cases outliers are the signal
"Test data can help training" Never — that's data leakage
"Labeling is quick and cheap" Often a major cost and schedule item
"Prepare once, done forever" Pipelines rerun every iteration and in production

4. AI Project Manager Perspective

Responsibilities

  • Plan and budget for the largest phase (time, people, labeling costs).
  • Ensure repeatable pipelines, not one-off manual scripts.
  • Oversee labeling operations: guidelines, quality checks, vendor management.
  • Guard against data leakage and bias introduction.
  • Track data preparation progress with clear milestones.
  • Maintain documentation (transformations applied, versions).

Stakeholders

Stakeholder Role
Data engineers Build pipelines, ETL/ELT
Data scientists Feature engineering, splits, imbalance handling
Labelers / SMEs Annotate data correctly
Business SMEs Provide domain knowledge for features
IT/security Secure processing environments
Compliance Approve anonymization/synthetic approaches

Risks

  • Schedule blowout — underestimating prep effort (most common!).
  • Data leakage → false confidence, production failure.
  • Bias amplification through careless cleaning/sampling.
  • Label noise from unclear guidelines.
  • Non-reproducible manual preparation.
  • Losing outlier signal in anomaly use cases.

Best Practices

  • Budget 60–80% of project effort here — communicate this to sponsors.
  • Automate with pipelines; version datasets and transformations.
  • Write labeling guidelines; measure inter-annotator agreement.
  • Split data before any tuning; lock the test set away.
  • Involve domain experts in feature engineering.
  • Document everything for auditability (needed in regulated industries).

5. Real-World Example (Healthcare — Diabetic Risk Prediction)

Scenario: A hospital predicts which patients risk developing diabetes (Phase I: Predictive Analytics; Phase II: EMR data approved with known quality gaps).

Phase III step by step: 1. Cleaning: 15% of BMI values missing → impute with median by age group. Remove duplicate patient records. Fix invalid entries (glucose = 0). 2. Standardization: Merge lab units (mg/dL vs mmol/L) into one unit. 3. Transformation: Normalize lab values; one-hot encode gender and smoking status. 4. Feature engineering (with doctors): Create "BMI trend over 2 years", "family history flag", "HbA1c change rate" — clinically meaningful features. 5. Labeling: Label = "developed diabetes within 3 years" derived from diagnosis codes; clinicians validate a sample of labels. 6. Imbalance: Only 8% positive cases → apply class weighting. 7. Split: 70/15/15 train/validation/test, split by patient (so the same patient never appears in both train and test — avoids leakage). 8. Pipeline: All steps automated so next iteration (new EMR data) reruns in hours, not weeks.

7. Key Formulas or Frameworks

Preparation Workflow

Clean → Transform → Engineer Features → Label → Balance → Split → Pipeline (Mnemonic: "CTELBSP" or story: Clean The Engine, Label Boxes, Split Properly.)

Imputation Options

  • Numeric missing → mean/median (median if outliers exist)
  • Categorical missing → mode or "Unknown" category
  • Advanced → model-based imputation

Split Ratios

Common: 70/15/15 or 80/10/10 (train/validation/test).

9. Exam Tips

Memory Tricks

  • "80/80 rule": ~80% of data is unstructured (Phase II) and up to ~80% of effort is data prep (Phase III).
  • Leakage = lying to yourself — great lab scores, dead in production.
  • Fraud/anomaly projects: outliers are gold, don't delete.
  • "Assess in II, Fix in III."

Keywords

  • "Clean, transform, feature engineering, labeling"
  • "Most time-consuming phase"
  • "Train/validation/test split", "hold-out test set"
  • "Data leakage", "imputation", "augmentation"

Differentiators

Pair Difference
Normalization vs Standardization 0–1 range vs mean-0/std-1
Feature engineering vs selection Create new features vs choose among existing
Augmentation vs Synthetic Modify real data vs generate new artificial data
Validation vs Test set Tuning vs final untouched evaluation

Traps

  • "Spend most time on modeling" → wrong; prep dominates.
  • "Use the test set to improve the model" → leakage, wrong.
  • "Delete all outliers" in a fraud scenario → wrong.
  • Doing prep manually with no pipeline → unsustainable for iterations.

11. Quick Revision Sheet

  • Phase III = HOW to prepare data — cleaning, transformation, features, labels, splits.
  • Consumes 60–80% of total project effort — the biggest phase.
  • Cleaning: missing (impute), duplicates, errors, outliers, standardize.
  • Don't remove outliers in anomaly/fraud use cases.
  • Transformation: normalize, standardize, encode (one-hot), bin, aggregate.
  • Feature engineering (domain-driven new inputs) is a top performance driver.
  • Labeling enables supervised learning — plan cost, guidelines, quality checks.
  • Augmentation/synthetic data expand scarce datasets.
  • Split train/validation/test; test set stays locked → avoid data leakage.
  • Fix class imbalance (oversample/undersample/weights).
  • Automate via pipelines (ETL/ELT); version and document everything.

⭐ Top 10 Things to Remember for the Exam

  1. Phase III = biggest effort: 60–80% of the project.
  2. Assess in II, fix in III — cleaning belongs here.
  3. Median imputation beats mean when outliers exist.
  4. Keep outliers in fraud/anomaly use cases.
  5. Feature engineering with domain experts drives performance.
  6. Labeling is costly — plan budget, guidelines, quality checks.
  7. Train/Validation/Test — lock the test set.
  8. Data leakage = inflated lab results, production failure.
  9. Augmentation & synthetic data solve scarcity and privacy limits.
