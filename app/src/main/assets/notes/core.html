2. Key Concepts

2.1 AI vs ML vs Deep Learning (nesting dolls)

┌───────────── ARTIFICIAL INTELLIGENCE ─────────────┐
│  Machines showing human-like intelligence         │
│  ┌────────── MACHINE LEARNING ────────────┐       │
│  │  Systems that LEARN from data          │       │
│  │  (no explicit programming of rules)    │       │
│  │  ┌────── DEEP LEARNING ──────┐         │       │
│  │  │ Multi-layer neural nets   │         │       │
│  │  │ for images/text/audio     │         │       │
│  │  └───────────────────────────┘         │       │
│  └────────────────────────────────────────┘       │
└───────────────────────────────────────────────────┘
  • AI: broad goal — machines performing tasks needing human-like intelligence.
  • ML: the dominant approach — learn patterns from data instead of hand-coding rules.
  • Deep Learning (DL): ML using multi-layer neural networks; shines on unstructured data; needs lots of data/compute; less explainable.
  • Narrow (weak) AI: good at ONE task (all AI today). General (strong) AI / AGI: human-level across tasks (does not exist). Exam expects realistic framing: today's AI = narrow.

2.2 Cognitive Technology & Probabilistic Systems

  • AI systems are probabilistic: outputs are predictions with confidence, not guaranteed answers.
  • Traditional software is deterministic: coded rules, same input → same output.
  • Consequences (exam-favorite): AI needs training data, produces errors by design, requires continuous monitoring/retraining, and success is measured statistically.

2.3 The DIKUW Pyramid

            ▲  WISDOM        — knowing WHY / best action, judgment
           ▲▲  UNDERSTANDING — insight into causes, "why it happens"
          ▲▲▲  KNOWLEDGE     — applied, contextualized information ("how")
         ▲▲▲▲  INFORMATION   — organized/processed data ("who/what/where/when")
        ▲▲▲▲▲  DATA          — raw facts and signals
  • Data: raw values ("₹5,000, 2:31 AM, Card #123").
  • Information: data with context ("Card #123 spent ₹5,000 at 2:31 AM in Dubai").
  • Knowledge: patterns applied ("this customer never shops abroad at night").
  • Understanding: why it matters ("this matches fraud behavior").
  • Wisdom: best action with judgment ("block and verify via call — balancing risk vs customer experience").
  • Exam point: AI helps climb the pyramid; most ML operates around information → knowledge/understanding; wisdom remains largely human.

2.4 Types of Machine Learning (consolidated)

Type Data Output Business Examples
Supervised Labeled Classification (category) or Regression (number) Fraud yes/no, price forecast, churn
Unsupervised Unlabeled Clusters, associations, reduced dimensions Customer segmentation, market basket
Semi-supervised Few labels + many unlabeled Same as supervised Document classification at scale
Reinforcement Reward signals from environment Action policy Routing, robotics, game AI

2.5 Data-Centric vs Model-Centric AI

Aspect Model-Centric Data-Centric (CPMAI-endorsed)
Focus Better algorithms/architectures Better data quality, labels, coverage
Data treated as Fixed The thing to improve
Typical gain source Marginal tuning Often larger, cheaper improvements
Slogan "Improve the code" "Improve the data"
- CPMAI mindset: AI projects are data projects → most wins come from cleaner, better-labeled, more representative data (hence Phases II–III dominate effort).

2.6 Why AI Projects Fail (and CPMAI's antidotes)

Failure Cause CPMAI Antidote
No clear business problem ("tech looking for a problem") Phase I business-first, go/no-go
Data unavailable / poor quality discovered late Phase II data understanding early
Underestimating data preparation Phase III planned as 60–80% effort
Measuring only technical metrics Phase V two-level (business+technical) evaluation
"Deploy and forget" — drift kills value Phase VI monitoring/retraining
Big-bang, multi-year waterfall scope Think Big, Start Small, Iterate Often
Unrealistic expectations (AI = magic) Probabilistic framing, stakeholder education
Ethics/bias as afterthought Ethics woven through every phase
- Widely cited statistic: a large majority (~80%+) of AI projects fail to reach production value — mostly for management, not technology reasons.

2.7 CPMAI Methodology — The Frame That Holds It All

  • Six phases: I Business → II Data Understanding → III Data Prep → IV Modeling → V Evaluation → VI Operationalization.
  • Heritage: built on CRISP-DM, upgraded with AI-specific practices (patterns, ethics, drift, MLOps) and agile iteration.
  • Iterative, not waterfall: short cycles; every iteration touches all six phases; scope grows gradually.
  • Vendor/technology-neutral and applicable to any AI pattern.
  • Agile alignment: small increments, working solutions over big documents, feedback loops, adaptability — but with data-project discipline added (agile alone isn't enough for AI; data work needs its own phases).

2.8 AI Ethics & Responsible AI (cross-phase thread)

  • Principles: fairness, transparency/explainability, accountability, privacy, safety/security, human oversight.
  • Bias enters via unrepresentative data, historical prejudice in labels, proxy variables (e.g., pincode ≈ community).
  • Governance artifacts: data consent, model documentation, audit trails, human-in-the-loop for high-stakes calls.
  • Trustworthy AI is a project requirement, not an optional add-on.

3. PMI CPMAI Exam Focus

What the Exam Expects

  • Place AI/ML/DL correctly; state that current AI is narrow.
  • Walk the DIKUW levels for a scenario.
  • Classify scenarios into ML types instantly.
  • Champion data-centric thinking and effort distribution.
  • Recite failure causes and match them to CPMAI phase remedies.
  • Explain CPMAI's CRISP-DM + agile heritage and iterative nature.

Frequently Tested

  1. "Raw numbers vs organized report vs actionable insight" → DIKUW levels.
  2. "Which is broader — AI or ML?" → AI ⊃ ML ⊃ DL.
  3. "Team keeps swapping algorithms with no gain; data is messy" → go data-centric.
  4. "Why did the AI project fail?" → almost always a business/data/management cause.
  5. "Is CPMAI waterfall?" → NO, iterative.
  6. Ethics scenarios: proxy bias, consent, explainability duty.

Common Misconceptions

Misconception Truth
"AI and ML are the same" ML is a subset of AI
"Today's AI is nearly AGI" It's narrow AI — one task at a time
"Better algorithms fix bad data" GIGO; data-centric wins
"Failures are due to weak tech" Mostly management/data/business causes
"CPMAI = documentation-heavy waterfall" Lightweight, agile-iterative
"Ethics slows projects, do it later" Late ethics = rework, legal risk, harm

4. AI Project Manager Perspective

Responsibilities

  • Educate stakeholders: probabilistic nature, narrow AI limits, data-first economics.
  • Enforce data-centric effort allocation and iteration discipline.
  • Maintain a risk register mapping classic failure causes to mitigations.
  • Own responsible AI checklists across phases.
  • Translate DIKUW: ensure projects deliver decision value, not just dashboards.

Stakeholders

  • Sponsors (expectation-setting), data & ML teams (execution), compliance/ethics boards, end users, customers/society (fairness impact).

Risks

  • Hype-driven scope, data debt, ethics debt, iteration fatigue ("why revisit Phase I again?"), metric myopia.

Best Practices

  • Run an AI literacy session at kickoff (narrow AI, probabilistic, data-first).
  • Keep a visible failure-cause checklist reviewed each iteration.
  • Institutionalize ethics gates in Phases I, III, V, VI.
  • Celebrate stopped projects that saved money — governance success.

Decision-Making Approach

Any AI decision, any phase:
  Business value clear? → data sufficient? → simplest approach? →
  ethical/compliant? → measurable? → iterate small?
  All yes → proceed. Any no → fix the "no" first.

5. Real-World Example (Retail — From Data to Wisdom, Done Right)

Scenario: A supermarket chain wants "AI for better stocking."

  1. DIKUW framing: POS records (Data) → weekly sales by store/SKU (Information) → "monsoon weeks spike umbrella + pakora-mix sales in Pune" (Knowledge) → "rain drives comfort-food buying" (Understanding) → "auto-raise stock 30% when IMD forecasts rain, cap by shelf life" (Wisdom, human-approved policy).
  2. ML typing: demand forecasting = supervised regression; store clustering for assortment = unsupervised.
  3. Data-centric moment: early models flop; instead of new algorithms, the team fixes promo-data gaps and SKU-code inconsistencies → accuracy jumps — data beat models.
  4. Failure-avoidance: business KPI (stock-outs −30%) fixed in Phase I; pilot = 1 city, top 500 SKUs (start small); monitoring for festival-season drift planned in Phase VI.
  5. Iteration 2 expands cities and adds a Hyperpersonalization pattern (personalized offers) — the loop continues.

7. Key Formulas or Frameworks

  • AI ⊃ ML ⊃ Deep Learning.
  • DIKUW: Data → Information → Knowledge → Understanding → Wisdom ("Don't Ignore Knowledge, Use Wisdom").
  • GIGO + Data-centric: improve data before improving models.
  • Think Big, Start Small, Iterate Often — CPMAI's agile heartbeat.
  • Two-question AI test: (1) Does it need learning from data? (2) Which of the 7 patterns? — else rules/RPA/BI.
  • Responsible AI pillars: Fairness, Explainability, Accountability, Privacy, Safety, Human oversight ("FEAPSH" or invent your own!).

9. Exam Tips

Memory Tricks

  • Nesting dolls: AI (biggest) → ML → DL (smallest).
  • DIKUW ladder story: numbers → report → pattern → why → best action.
  • "Fix the data first" — when a scenario shows messy data + algorithm-hopping, the data-centric answer wins.
  • Failure question reflex: the cause is business/data/management ~always — never "the algorithm was unlucky."

Keywords

  • "AI projects are data projects"
  • "Narrow AI", "probabilistic"
  • "Iterative, built on CRISP-DM"
  • "Responsible/trustworthy AI", "bias", "explainability"

Differentiators

Pair Difference
AI vs ML Goal vs data-learning approach (subset)
ML vs DL Family vs neural multi-layer subset
Information vs Knowledge Organized facts vs applied patterns
Data-centric vs Model-centric Improve data vs improve algorithm
CPMAI vs CRISP-DM AI-ready, agile-iterative extension vs original data-mining process

Traps

  • "Buy a better algorithm to fix bad data" → wrong.
  • "AI will fully replace human wisdom/judgment" → wrong (top of DIKUW stays human).
  • "Run CPMAI phases once, sequentially, then done" → wrong (iterate).
  • "Ethics review only before launch" → wrong (every phase).
