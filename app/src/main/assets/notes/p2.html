1. Topic Overview

Definition

Phase II: Data Understanding is the second CPMAI phase. Here you identify WHAT data is needed to solve the business problem defined in Phase I, find where it lives, assess its quality and quantity, and make a data go/no-go decision.

One-line memory hook: Phase I = WHY. Phase II = WHAT data?

Why It Is Important

  • AI projects are data projects. No good data = no AI, no matter how good the algorithm.
  • "Garbage In, Garbage Out" (GIGO): bad data produces bad models.
  • Many projects die here — data may be missing, siloed, poor quality, or legally unusable.
  • Prevents spending months on modeling only to discover the data can't support the use case.

Where It Is Used in AI Projects

  • Immediately after Phase I, in every iteration.
  • Whenever new data sources are added or the use case is expanded.
  • During data audits, data feasibility studies, and exploratory data analysis (EDA).

2. Key Concepts

2.1 Data Requirements

Derived directly from the Phase I business problem: - What data is needed (e.g., transactions, images, text)? - How much data (volume/quantity)? - What quality level is acceptable? - What labels are required (for supervised learning)?

2.2 Data Types

Type Meaning Examples
Structured Organized in rows/columns Bank transactions, Excel, SQL tables
Semi-structured Partial structure with tags JSON, XML, emails, log files
Unstructured No predefined format Images, videos, audio, free text, X-rays

Exam note: Roughly 80% of enterprise data is unstructured — a big reason AI (especially the Recognition pattern) is valuable.

2.3 Data Sources

Source Examples
Internal Core banking system, CRM, ERP, POS logs, EMR/EHR
External Purchased datasets, open/public data, social media, partner data
Generated Synthetic data, sensor/IoT streams, user-generated content

2.4 The Big Data "V's"

V Meaning Example
Volume How much data Billions of card transactions
Variety Different formats/types Text + images + tables
Velocity Speed of data arrival Real-time payment streams
Veracity Trustworthiness/quality Duplicate or wrong entries reduce veracity
(Value) Business usefulness Data must serve the Phase I goal

2.5 Data Quality Dimensions (heavily tested)

Dimension Question Bad Example
Accuracy Is it correct? Wrong birth dates
Completeness Anything missing? 40% of income fields blank
Consistency Same across systems? "M/F" in one system, "Male/Female" in another
Timeliness Is it fresh enough? 5-year-old customer addresses
Validity Follows rules/formats? Phone number = "ABC123"
Uniqueness Duplicates removed? Same customer twice

2.6 Data Quantity

  • Supervised learning often needs thousands of labeled examples per class.
  • More complex problems (deep learning) → more data.
  • Too little data is a valid no-go reason or a reason to descope/use simpler methods.

2.7 Exploratory Data Analysis (EDA)

  • First look inside the data: distributions, ranges, missing values, outliers, correlations.
  • Done with statistics and visualizations (histograms, scatter plots).
  • Purpose: understand what you have before cleaning (Phase III).

2.8 Data Governance, Privacy & Access

  • Who owns the data? Do we have rights to use it?
  • Regulations: GDPR (EU), HIPAA (US healthcare), RBI/DPDP Act (India).
  • PII (Personally Identifiable Information) must be protected/anonymized.
  • Data locked in silos or with legal restrictions can block the project.

2.9 Data Go/No-Go

End of Phase II asks: "Do we have enough, good-enough, legally usable data?" - Yes → proceed to Phase III. - No → find more data, fix quality, descope, or stop.

3. PMI CPMAI Exam Focus

What the Exam Expects

  • Phase II comes after business understanding and before data preparation.
  • Identify data requirements from the business problem, not from "whatever data we have."
  • Know the quality dimensions and the V's.
  • Understand structured vs unstructured data and the ~80% unstructured fact.
  • The data go/no-go concept.

Frequently Tested

  1. "The team found the needed data doesn't exist / is poor quality — what phase caught this?" → Phase II.
  2. Matching quality problems to quality dimensions.
  3. Internal vs external data sourcing decisions.
  4. Privacy/regulatory checks on data (GDPR/HIPAA).
  5. GIGO principle.

Common Misconceptions

Misconception Truth
"Clean the data in Phase II" Cleaning is Phase III; Phase II only assesses
"More data is always better" Quality and relevance matter more than raw volume
"If data exists, we can use it" Legal/privacy rights must be verified
"Data understanding is a one-time task" Repeats every iteration

4. AI Project Manager Perspective

Responsibilities

  • Translate Phase I business needs into data requirements.
  • Inventory data sources; negotiate access with data owners.
  • Commission data quality assessment and EDA.
  • Engage legal/compliance on privacy and usage rights.
  • Estimate cost/effort of acquiring or labeling data.
  • Drive the data go/no-go decision.

Stakeholders

Stakeholder Role in Phase II
Data owners / stewards Grant access, explain data meaning
Data engineers Extract and profile data
Data scientists Perform EDA, judge sufficiency
Legal/compliance/DPO Privacy, consent, regulations
Business SMEs Explain what fields actually mean
IT/security Secure access, infrastructure

Risks

  • Required data doesn't exist or is too sparse.
  • Poor quality (incomplete, inconsistent, outdated).
  • Data silos and ownership disputes.
  • Privacy/regulatory violations (using data without consent).
  • Bias in data (unrepresentative samples → unfair models).
  • Underestimating labeling cost/effort.

Best Practices

  • Start from business requirements → data requirements (never the reverse).
  • Create a data inventory/catalog with source, owner, quality notes.
  • Do EDA early; involve business SMEs to interpret fields.
  • Check representativeness to avoid bias.
  • Document data lineage (where it came from).

5. Real-World Example (Retail — Demand Forecasting)

Scenario: A retail chain wants to predict weekly demand per store per product (Phase I: Predictive Analytics pattern, KPI = reduce stock-outs 30%).

Phase II step by step: 1. Data requirements: 2–3 years of sales history per store/SKU, promotions calendar, prices, holidays, weather. 2. Source inventory: Sales → POS system (internal). Promotions → marketing Excel sheets (internal, messy). Weather → external API. Holidays → public data. 3. EDA findings: 18 months of clean POS data available (not 3 years); 25% of promotion records missing dates; two stores changed SKU codes mid-year (consistency issue). 4. Quality assessment: Completeness issue (promotions), consistency issue (SKU codes), timeliness OK. 5. Quantity check: 18 months × 200 stores × 5,000 SKUs = enough volume for a first iteration. 6. Legal check: All internal + public data → no privacy issues. 7. Data go/no-go: GO, with scope note: first iteration uses 18 months of data and top 500 SKUs only (start small), promotion data to be fixed in Phase III.

7. Key Formulas or Frameworks

Business → Data Mapping Framework

Business Problem → Prediction Target → Required Inputs (features)
→ Data Sources → Quality/Quantity/Legal Assessment → Data Go/No-Go

The V's of Big Data

Volume, Variety, Velocity, Veracity (+ Value) — memorize as "4V + Value".

Data Quality Dimensions

Mnemonic: "A CC TVU" → Accuracy, Completeness, Consistency, Timeliness, Validity, Uniqueness.

9. Exam Tips

Memory Tricks

  • Phase II = WHAT data (I=WHY, III=HOW to prepare).
  • Quality dimensions: A-CC-TVU.
  • GIGO — quality first, always.
  • "Assess in II, Fix in III" — understanding vs preparation.

Keywords Signaling Right Answers

  • "Identify data requirements from the business problem"
  • "Assess data quality and quantity"
  • "Verify data rights/privacy"
  • "Data feasibility / data go/no-go"

Differentiators

Pair Difference
Phase II vs Phase III II = assess/understand; III = clean/prepare
Accuracy vs Validity Accuracy = factually correct; Validity = correct format/rules
Volume vs Veracity Volume = amount; Veracity = trustworthiness

Traps

  • Options that clean/transform data in Phase II → wrong phase.
  • "Use whatever data we already have" without business mapping → wrong.
  • Ignoring legal/privacy review → wrong.
