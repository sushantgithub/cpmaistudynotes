1. Topic Overview

Definition

Phase VI: Model Operationalization puts the approved model into real-world production use and keeps it healthy over time — covering deployment, monitoring, drift management, retraining, governance, and continuous improvement (often called MLOps / ModelOps).

One-line memory hook: Phase VI = RUN & MAINTAIN — "a model is not done when deployed; that's when its life begins."

Why It Is Important

  • A model creates zero business value until it is used in production.
  • AI models degrade over time (drift) — unlike traditional software, "deploy and forget" guarantees failure.
  • Many AI projects die at the "last mile": great models that never reach or survive production.

Where It Is Used

  • After Phase V approval; then continuously through the model's life.
  • Feeds learnings back into new iterations (→ Phase I again).

2. Key Concepts

2.1 Deployment Options

Option Meaning Example
Batch (offline) inference Model runs on schedules over data batches Nightly churn scores for all customers
Real-time (online) inference Model answers requests instantly via API Fraud score during a card swipe (milliseconds)
Edge deployment Model runs on local devices Defect camera on a factory line; phone-based face unlock
Cloud / on-prem / hybrid Where the serving infrastructure lives Cloud API vs bank's own data center (data residency rules)

2.2 Deployment/Release Strategies

Strategy Meaning
Shadow deployment New model runs in parallel; outputs logged, not acted on
Canary release Small % of traffic first, expand gradually
Blue-green Two environments; instant switch/rollback
A/B testing Compare model vs control on live segments
Human-in-the-loop Model recommends; human approves critical actions

2.3 Model Drift (top exam topic!)

Drift Type What Changes Example
Data drift Input data distribution changes Post-COVID spending patterns differ from training data
Concept drift The input→output relationship changes Fraudsters invent new tactics; "what fraud looks like" changes
  • Result: model performance decays over time.
  • Response: monitor → detect → retrain/rebuild (loop back through CPMAI phases).

2.4 Monitoring (what to watch)

Category Metrics
Model performance Precision/recall/error rates vs baselines
Data quality/drift Input distributions, missing values, schema changes
Business KPI Is the Phase I KPI still being achieved?
Operational Latency, throughput, uptime, cost per prediction
Fairness Subgroup performance over time
- Set alert thresholds; define who responds and how.

2.5 Retraining Strategies

  • Scheduled: retrain every X weeks/months.
  • Trigger-based: retrain when drift/performance alerts fire.
  • Continuous/online learning: model updates as data flows (higher risk, needs guardrails).
  • Retraining = mini-iteration through Phases III–V before redeployment.

2.6 MLOps (Machine Learning Operations)

  • MLOps = DevOps principles applied to ML: automation, CI/CD, versioning, monitoring, collaboration between data science and IT/ops.
  • Key components:
  • Version control for code + data + models (every prediction traceable to model/data version).
  • CI/CD pipelines for automated testing and deployment of models.
  • Model registry: catalog of models, versions, stages (staging/production/archived).
  • Feature store: shared, consistent features across training and serving (prevents training-serving skew).
  • Automated retraining pipelines.

2.7 Governance, Compliance & Auditability

  • Model inventory/registry with owners and risk ratings.
  • Audit trails: which model version made which decision, when, on what data.
  • Explainability in production: reason codes for decisions (loans, claims).
  • Access control & security: protect models and data; watch for adversarial attacks.
  • Regulatory needs: RBI model risk guidelines, GDPR, EU AI Act-style obligations, HIPAA.

2.8 Change Management & Adoption

  • Users must trust and adopt the model: training, communication, feedback channels.
  • Define human override processes.
  • Track adoption metrics — an unused model delivers no ROI.

2.9 Continuous Improvement Loop

  • Production learnings (errors, edge cases, user feedback, drift) feed the next iteration → back to Phase I with expanded scope ("Think Big, Start Small, Iterate Often" completes here).
  • Also plan model retirement/decommissioning when value ends.

3. PMI CPMAI Exam Focus

What the Exam Expects

  • Deployment is the beginning of the model's operational life, not the project's end.
  • Define and distinguish data drift vs concept drift.
  • Know batch vs real-time vs edge deployment fit-for-purpose.
  • MLOps essentials: versioning, CI/CD, monitoring, model registry, retraining.
  • Governance: auditability, explainability, human-in-the-loop.

Frequently Tested

  1. "Model performance dropped 6 months after deployment" → drift → monitor & retrain.
  2. "Fraudsters changed tactics" → concept drift.
  3. "Customer behavior distribution changed" → data drift.
  4. Millisecond decisions → real-time; nightly scoring → batch; no-connectivity factory → edge.
  5. "Deploy and forget" answers are always wrong.
  6. Safe rollout: shadow/canary before full traffic.

Common Misconceptions

Misconception Truth
"Project ends at deployment" Monitoring/retraining continue for the model's life
"Models stay accurate forever" Drift degrades them — plan retraining
"MLOps = just DevOps" Adds data + model versioning, drift monitoring, retraining
"Full rollout immediately" Prefer shadow/canary/A-B staged rollouts
"Monitoring = uptime only" Includes performance, drift, business KPI, fairness

4. AI Project Manager Perspective

Responsibilities

  • Plan the deployment approach (batch/real-time/edge; rollout strategy) with architects.
  • Establish the monitoring plan: metrics, thresholds, alert owners, response runbooks.
  • Define retraining policy and budget for ongoing operations (models have OPEX!).
  • Ensure governance artifacts: registry entry, audit trails, explainability, approvals.
  • Drive adoption/change management with end users.
  • Schedule post-deployment KPI reviews vs Phase I targets; plan next iterations.
  • Plan rollback and decommissioning procedures.

Stakeholders

Stakeholder Role
ML engineers / MLOps team Deploy, automate, monitor
IT operations / SRE Infrastructure, uptime, incident response
Data engineers Production data pipelines, feature store
Business owners/users Adoption, feedback, KPI ownership
Compliance/risk/audit Ongoing regulatory adherence
Security Model/data protection, adversarial threats

Risks

  • Silent model decay (no monitoring) → bad decisions at scale.
  • Training-serving skew (production features differ from training features).
  • No rollback plan → prolonged outages/damage.
  • Unbudgeted operations — sponsors assume "done" at go-live.
  • Adoption failure — users bypass the model.
  • Compliance gaps — undocumented model decisions.
  • Security/adversarial attacks (fraudsters probing the model).

Best Practices

  • Monitor from day one; alert on drift and KPI decay.
  • Stage rollouts: shadow → canary → full, with rollback ready.
  • Version everything (code, data, model); use a model registry.
  • Automate retraining pipelines; treat retrains as mini-CPMAI iterations.
  • Keep humans in the loop for high-stakes decisions.
  • Review business KPI quarterly; retire models that stop paying off.

5. Real-World Example (Manufacturing — Predictive Maintenance)

Scenario: A manufacturer deploys a model predicting machine bearing failures 2 weeks ahead (Phase I KPI: reduce unplanned downtime 25%).

Phase VI step by step: 1. Deployment choice: Edge inference on factory-floor gateways (low latency, works despite patchy connectivity), with cloud dashboard aggregation. 2. Rollout: Shadow mode for 4 weeks on Line 1 (predictions logged, maintenance unchanged) → accuracy confirmed → canary on 2 lines → full rollout to 12 lines. 3. Monitoring: Sensor input distributions (vibration/temperature) tracked for data drift; precision/recall of failure alerts tracked monthly; downtime KPI on the executive dashboard; alert latency <1s. 4. Drift event: After 7 months, new bearing supplier → vibration signatures shift → data drift alert fires → data from new bearings collected/labeled → model retrained (Phases III–V mini-cycle) → redeployed via canary. 5. Governance: Every alert stores model version + input snapshot; maintenance overrides logged (human-in-the-loop). 6. Adoption: Technicians trained; feedback button on alerts ("useful / false alarm") feeds evaluation. 7. KPI review: Quarter 2 shows downtime reduced 28% ✔ → business approves next iteration: extend model to pumps and conveyors (back to Phase I).

7. Key Formulas or Frameworks

MLOps Pillars

Version (code+data+model) → Automate (CI/CD) → Monitor (perf+drift+KPI) → Retrain → Govern. Mnemonic: "VAMRG" → "Very Awesome Models Require Guarding."

Rollout Ladder

Shadow → Canary → A/B → Full (each step de-risks the next).

Retraining Triggers

Scheduled (time-based)  OR  Triggered (drift/perf alert)  OR  Continuous (online)

9. Exam Tips

Memory Tricks

  • "Deployment is a birthday, not a funeral" — the model's life starts at go-live.
  • Drift memory: Data drift = inputs; Concept drift = meaning (X→Y).
  • Speed test: milliseconds → real-time; nightly → batch; offline device → edge.
  • MLOps = DevOps + Data + Drift.

Keywords

  • "Monitor for drift and retrain"
  • "Model registry, versioning, audit trail"
  • "Shadow/canary rollout", "rollback plan"
  • "Business KPI review post-deployment"

Differentiators

Pair Difference
Data vs Concept drift Input distribution vs input-output relationship
Shadow vs Canary No live impact vs small live traffic slice
Batch vs Real-time Scheduled bulk vs instant per-request
DevOps vs MLOps Software only vs software + data + models + drift

Traps

  • Any "deploy and the project is complete" option → wrong.
  • "Models don't need retraining" → wrong (drift!).
  • "Roll out to 100% immediately" in high-stakes cases → prefer staged rollout.
  • "Monitoring = server uptime" → incomplete; include performance/drift/KPI/fairness.

11. Quick Revision Sheet

  • Phase VI = deploy + monitor + maintain — value starts (not ends) at go-live.
  • Serving modes: batch / real-time / edge (+cloud/on-prem/hybrid).
  • Rollout ladder: shadow → canary → A/B → full, with rollback ready.
  • Data drift = input distribution changes; concept drift = X→Y meaning changes.
  • Monitor: performance, drift, business KPI, operational, fairness — with alert thresholds.
  • Retraining: scheduled / trigger-based / continuous → mini-cycle through Phases III–V.
  • MLOps: versioning (code+data+model), CI/CD, model registry, feature store, automation.
  • Governance: audit trails, explainability, human-in-the-loop, security.
  • Drive user adoption — unused models earn zero ROI.
  • Plan operations budget and eventual model retirement.
  • Learnings feed the next iteration → back to Phase I.
